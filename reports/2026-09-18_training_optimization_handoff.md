## Что выяснено и какие идеи остаются гипотезами

| Идея / утверждение | Свидетельство и статус |
|---|---|
| Батч 16 выгоднее 4 по throughput | Старый smoke: 1.140 с/итер против 0.434 при четырёхкратном батче. Это не доказательство равного качества при меньшем числе обновлений. Старый счётчик делил на запрошенные, а не реальные итерации. |
| «Запас инженерного ускорения исчерпан, остаётся максимум 10%» | Не принимается как доказанный вывод: три точки времени не являются GPU-профилем. Слияние операций, иной layout и другая карта не ограничены свободным членом линейной подгонки. |
| Статистики активности можно считать на GPU | Подтверждено кодом: штатный solver копирует весь тензор на CPU ради mean/min/max. Реализовано; скорость проверяется текущим worker. |
| ReLU можно перенести перед gather | Подтверждено формулой штатного PPNeuronIGRSynapses и офлайн-сравнением forward/backward. Реализовано; CUDA и скорость проверяются текущим worker. |
| Sparse matrix multiplication / fused gather-reduce | Кандидат после профиля; не реализован, выигрыша не измеряли. Обязательны градиенты по общим параметрам типов, не только forward. |
| torch.compile / CUDA graphs | Кандидат после профиля; не реализован. Ограничение «≤10%» не доказано; источником graph breaks могут быть AutoDeref/RefTensor. |
| AMP / fp16 | Не реализовано. Одного autocast недостаточно для обещания ускорения gather/scatter. Нужны реальные dtype и численная проверка рекуррентной динамики. |
| Ранняя остановка / меньше дообучения из переноса | Возможная экономия по числу обновлений, но данных о сходимости нет. «Нулевая научная цена» неверно: проверить task-loss и биологическую валидацию, с контрольным запуском. |
| L4 | Пока не запускалась здесь. При цене только GPU она должна обогнать T4 примерно в 1.35 раза для безубыточности; CPU/RAM меняют общий порог. Запрет выше L4 сохраняется. |
| Несколько процессов на T4 | Прежние измерения давали небольшой выигрыш; текущий стенд последовательный. Ни обещаний ансамбля, ни новых packed-запусков нет. |

## Как прочитать завершённый benchmark

В каталоге Volume искать `manifest.json`, `records.json`, `comparisons.json`,
каталоги вариантов с `result.json`, `stdout.log`, `evidence/{initial,final}.pt`,
`evidence/losses.json`; у отдельного профиля `trace.json` и `operators.txt`.

Время `train_s` включает steady state, logging и checkpoints, исключает
создание solver и дополнительную запись evidence. `s_per_iter` делится на
`completed_iters`, не на запрошенные 30. Скорость профилированного запуска
в сравнение не включать. Два повтора дают разброс, не точный доверительный
интервал. При расхождении чисел сначала сравнить baseline-повторы — CUDA
scatter/reductions могут быть недетерминированными.

В любом исходе сохранить ошибку/числа и контроль в отчёте. Не объявлять
оптимизацию принятой, если численные проверки не прошли. Ошибка worker
не даёт разрешения на ещё один платный запуск.

## Итог запуска (дописан агентом Claude 2026-09-18, 22:30; сессия Codex закончилась по лимиту)

Run `2026-09-18_bench_150043_689575_229624b2a4`, Tesla T4, torch 2.14.0+cu130, батч 16, 30 итераций на вариант, два повтора в противоположном порядке; приложение остановилось в 22:18 (18 мин, ~$0,30). Записи: `data/benchmarks/<run>/` (`records.json`, `comparisons.json`, `manifest.json`, `operators.txt` профиля, `final.pt` трёх прогонов); `reports/runs.jsonl`; рисунок `reports/figures/2026-09-18_optimization_bench_t4.png` (`tools/summarize_training_benchmark.py`).

| вариант | с/итер, повтор 0 / 1 | ускорение к baseline того же повтора |
|---|---|---|
| baseline | 1,137 / 1,135 | 1,000 |
| stats | 1,096 / 1,102 | 1,036 / 1,033 |
| relu | 1,016 / 1,029 | 1,118 / 1,104 |
| stats_relu | 0,976 / 0,970 | **1,164 / 1,172** |

Пиковая память 4,47 ГБ во всех вариантах. Прогрев (свежий корень кэшей) занял 446 с — это цена изоляции каталога, в рабочем обучении кэш переиспользуется.

**Эквивалентность.** `comparisons.json` отмечает `close=False` для конечных состояний (max abs 1,6e-4 … 4,3e-4 при rtol 1e-4, atol 1e-6) и `close=True` для loss-кривых (≤1,2e-4). Дополнительная проверка, которой в стенде не было: два baseline между собой. Свободные параметры сети совпадают до 3e-8 во всех парах (baseline r0/r1, baseline/stats_relu); голова-декодер расходится на 3,0e-4 между двумя baseline и на 2,6e-4 / 1,4e-4 между baseline и stats_relu. Расхождение оптимизированного варианта не больше расхождения эталона с самим собой на CUDA (атомарные scatter в обратном проходе свёртки декодера): **правки эквивалентны в пределах собственной недетерминированности эталона**, а допуск стенда просто жёстче этого шума. Это не доказательство равного качества обученной модели — только 30 итераций.

**Профиль (baseline, 3 активных шага):** доля CUDA-времени — `mul` 20 %, `gather` 20 %, поэлементные ядра 18 %, `scatter_add` 12 %, ReLU (`clamp_min`) 8 %, `index_add` 8 %, `threshold_backward` 7 %, загрузчик данных 5 %, копия на CPU 2,6 %. Карта занята настоящими ядрами по рёбрам, свободного члена «задержки» в профиле нет; это согласуется с аффинной подгонкой отчёта исследования (0,18 с + 0,064 с × B) в том смысле, что выше батча 16 расходы — полоса памяти. Что остаётся: слить `mul`+ReLU+`gather` в одно ядро (или `torch.compile` этой цепочки) — до ~25 % по профилю; fp16 на рёберных тензорах — до 2× по полосе, с проверкой динамики.

**Вывод для дальнейшей работы:** `stats_relu` ускорил измеренные 30 итераций
на 16–17 % и доступен через `--variant stats_relu`. Формула forward та же;
начальные состояния совпали, потери прошли заданный допуск, но проверка
конечных состояний формально не прошла. Дополнительное сравнение с двумя
baseline показывает сопоставимый разброс головы-декодера. Долгое обучение
и качество на валидации не проверялись. Полное обучение не разрешено этим
стендом и не является текущим шагом (`ROADMAP.md`, 3').
