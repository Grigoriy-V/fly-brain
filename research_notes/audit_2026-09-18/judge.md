# Judge's verdict (adversarial feasibility audit, 2026-09-18)

Six auditors were each told to refute one leg of the project; a seventh judged. 7 agents, 1,447,929 subagent tokens, 55 minutes, Opus. This text is the agents' output: data the project agent checked, not a decision.

**Overall:** FEASIBLE_WITH_NAMED_CHANGES

Yes, the project is possible — but two of its advertised sentences are not, and one number that reordered the roadmap is probably a bug in the project's own code rather than a fact about the connectome. I re-ran the key attacks myself. (1) The decodability map is real: photoreceptors 1.000 against a floor of 0.117 (map.csv), and the frame component separates Borst's sustained (L3 0.629, Mi4 0.634, Mi9 0.592, Tm9 0.530) from transient (L1 0.336, L2 0.337, Mi1 0.282, Tm4 0.296) classes with zero overlap — biology the model was never fit to. (2) But the advertised deliverable, "the curve R -> L -> Mi/Tm -> T4/T5" (ROADMAP.md:110), is manufactured by one config line. Using flydream/decode with lags (0,2,4) instead of config.toml:37's lags = [0], and refitting the time-shuffle control at the same window, I reproduced the published lag-0 fits exactly (T5a 0.1878, L1 0.8485, R1 0.9999 — digit-for-digit map.csv) and then watched the ordering inverts: T5a's control-corrected score 0.057 -> 0.625, T5d 0.111 -> 0.534, TmY15 0.054 -> 0.417, T4a 0.141 -> 0.345, all above L1's 0.300, while L1 falls and Mi1 falls to 0.183. Even the raw PixCorr reshuffles (T5a 0.188 -> 0.782, above Mi1's 0.343). Stage explains only R2 = 0.317 of the map (r = -0.563, n = 65), 50.3% of the variance is within-stage, and "lobula/other" at 0.734 already sits out of order. There is a decodability map; there is no stage curve. (3) The "sample-shuffle floor" is not an information control: I computed the training-mean image's PixCorr against the test frames as 0.1169 against the published floor of 0.1170 (SD 0.0029 across all 65 types). It is the same number for every type and cannot establish per-type significance; Tm20 (0.1268) and Mi2 (0.1258) sit below their own time-shuffle controls. (4) The map is read from one member, and that member is not arbitrary: the 50 ensemble directories are strictly rank-ordered by validation loss (Spearman(id, loss) = 1.000, 5.1366 -> 5.6779), so config.toml:32's flow/0000/000 is the single best of 50 and step 2's members 000/001/002 are the top three — a selection no project document records, and the one whose consequences Lappalainen et al. (task performance predicts tuning realism) make non-trivial. No auditor found this. (5) The largest practical finding is the transplant. FlyVis parameterises syn_strength as 0.01/<N>_pair (flyvis/network/initialization.py:501) and weight = sign x syn_count x syn_strength (dynamics.py:165), but flydream/model/zero.py:96-106 copies the raw strength by type-pair key across connectomes. I built both networks and measured the mismatch: <N>_fv/<N>_mc has median 1.847, p95 7.156, max 34.18, and Tm9->T5a-d — T5's main excitatory driver — is underweighted 3.2-4.2x while TmY15->T4/T5, the only inhibition T5 has left after CT1 is missing, is overweighted 2-2.7x. So model zero's DSI 0.020 against FlyVis's 0.391 is at least partly a scaling error, not a verdict on MaleCNS — and that number is the stated reason the roadmap put item 4 before item 3 (DECISIONS.md:190-207). None of this is insurmountable, none of it costs money, and all of it is cheaper to fix now than after a Modal run.

## fatal

- The advertised figure of paper one — "the curve R -> L -> Mi/Tm -> T4/T5 with its controls" (ROADMAP.md:110-111) — as a STAGE curve. Verified by me on by_stage.csv: stage explains R2 = 0.317 (Pearson r = -0.563, n = 65), eta2(stage) = 0.497 so 50.3% of the variance is within-stage, the within-stage ranges (Tm/TmY 0.127-0.880) exceed every between-stage step (largest 0.179), and stage 6 (lobula/other, 0.734) already sits above stages 3-5. Chen et al. 2024, the project's own genre benchmark, report R > 0.9 against the mouse hierarchy. A map of decodability per cell type exists; a monotone curve through anatomical stages does not. The map survives, the curve does not.
- The ordering as published is not reproducible under a decoder choice the project's own report lists as unmeasured (reports/2026-09-18_step4_decoder_stack.md §6, "Лаг нулевой ... Временное окно есть настройкой, но не измерено"). I reproduced this myself with flydream/decode/{pairs,ridge,metrics}.py on the project's pairs.npz: at lags (0,2,4) = 60 ms, with the time-shuffle control refit at the same window, the control-corrected score goes T5a 0.0570 -> 0.6247, T5d 0.1107 -> 0.5341, TmY15 0.0542 -> 0.4173, T4a 0.1406 -> 0.3452, Tm9 0.5298 -> 0.6584, while L1 0.3361 -> 0.2999, R1 0.5793 -> 0.3577, Mi1 0.2816 -> 0.1830. The four types the map puts at the bottom all land above L1. Raw PixCorr moves too: T5a 0.1878 -> 0.7823, T5d 0.2371 -> 0.6770, Mi1 0.4137 -> 0.3428. Publishing any per-type ordering before sweeping `lags` would publish an artifact of config.toml:37.
- "An image can be reconstructed from model activity well enough to honestly call it reading the picture out of the brain" — fatal as a sentence, and AGENTS.md:28 already forbids it. There is no fly in the loop: the decoder reads activity the model itself generated from a stimulus the project handed it, and the only place reconstruction is perfect (photoreceptors, PixCorr 1.000) is where the stimulus is injected as external drive, which the project's own report already calls an obligatory result rather than an achievement. I verified auditor 2's oracle conversion on the 1,800 held-out frames: rank-8 = 0.691, rank-24 = 0.849, rank-64 = 0.930, so L1's 0.8485 is worth about 24 of 721 dimensions. (Caveat against that auditor: its deep-stage rank conversions are lag-0 numbers; with a 60 ms window L1 reaches 0.954, about 90 dimensions, and T5a 0.782. The overstatement is a factor of ~8, not ~28.) The weaker sentence the project already uses everywhere is fully supported by the same numbers; only the strong one has to go.
- Item 7's deliverable as written — "the second paper's material" from internally generated activity (ROADMAP.md:150-151). Auditor 4 ran the chapter's first experiment on both substrates and the decode in the dark returns the ridge prior at r = 0.96, identical under noise drive, with 99% of the stimulus-driven contrast and zero correlation with the injected drive. I did not re-run it, but it is structurally forced and consistent with what I did verify: ridge shrinks to its intercept when the regressor is uninformative, and that intercept is the training mean image, whose PixCorr against the test frames I measured as 0.1169 — exactly the published "floor". The roadmap's own safeguard (ROADMAP.md:147, the stimulus-subspace fraction) reads 0.60-1.00 in the dark because the OFF transient passes it, so it does not catch the artifact it was written for. The chapter survives as an afterglow curve plus a signed negative result; the promised positive content does not.
- The substrate spark (a language model or image generator made of fly wiring). Auditor 6's arithmetic is correct and the leg is unrecoverable by scope change — a frozen substrate contributes 0 trainable parameters while a GPT-2-vocabulary readout alone is 2.295e9. But note the cost of accepting this is zero: ROADMAP.md already Parked it on the human's word 2026-09-18 ("я бы начал не с LLM"), and auditor 6 spent its whole budget killing something already off the path. Its other conclusions are stale: it ran before map.csv was written at 05:12 and therefore states the Sintel map does not exist and that item 4 has produced no numbers.

## costly

- Item 3 (training MaleCNS on Modal) must not start from the transplant as built. Verified in code and by measurement: syn_strength is initialised as 0.01/<N>_pair (flyvis/network/initialization.py:501) and the edge weight is sign x syn_count x syn_strength (dynamics.py:165), so it is a connectome-relative gain; flydream/model/zero.py:96-106 copies it across connectomes by key. I built both networks and measured <N>_fv/<N>_mc over the 395 matched pairs: median 1.847, p5 0.606, p95 7.156, max 34.18. Tm9->T5a 4.15x, T5b 3.35x, T5c 3.17x, T5d 3.85x underweighted; TmY15->T4/T5 0.37-0.55x, i.e. 2-2.7x overweighted. The transplant simultaneously starves T5's main excitation and inflates the only inhibition it has left. Fix: initialise from the connectome-adaptive init, or rescale by <N>_fv/<N>_mc. Auditor 3 reports this alone lifts mean T4/T5 DSI from 0.025 to 0.159 with zero training (T4c 0.778, PD error 11.5 -> 7.4 deg) — I verified the mechanism and the factors, not that re-measurement. Cost: minutes of local CPU. Not doing it means buying a Modal run that starts where Tm9 is relu-silent.
- Item 3's validation target must either restore CT1 or drop T5 direction selectivity. ISS-0002 is confirmed in the record (CT1 bodyId 10157: 56,517 outgoing weight rows, 8 reaching a typed right-lobe neuron), sign and syn_count are requires_grad=False in flyvis (network.py:99-112), and a pathway with zero edges has no gain to train — so training cannot invent CT1. Auditor 3's ablation inside FlyVis (T5 DSI 0.587 -> 0.052, -91%; all 27 missing pathways together 0.050, i.e. CT1 is essentially the whole deficit) I did not re-run; if it holds, FlyVis-level T5 validation is unreachable on this export at any budget. The 'Ablations on model zero' line already in ROADMAP's Not started section settles this for free, locally.
- Item 4 needs the ensemble, and for a reason stronger than the contract. I found that the 50 ensemble directories are strictly rank-ordered by validation loss (Spearman(id, loss) = 1.000; 000 = 5.1366, median 5.3001, max 5.6779, SD 0.0745, CV 1.4%). config.toml:32 therefore selects the best member of 50, and step 2's 000/001/002 are the best three — a selection no document records. Validation-loss CV (1.4%) cannot stand in for tuning spread: the same three members' T4/T5 DSI is 0.547/0.344/0.281, CV 36% (runs.jsonl:12). Run the map on 10 members minimum and report per-type median with interval. Cost: 624 s per member locally (meta.json), ~2 h for 10 on CPU, or one Modal batch — a priced action with its own gate.
- The 'floor' must be replaced by a per-type null. I measured the training mean image's PixCorr against the 1,800 test frames as 0.1169 against the published sample-shuffle floor of 0.1170 (mean over 65 types, SD 0.0029); the test-set mean image alone reaches 0.1722 and seven types sit at or below it. The shuffle control measures that ridge shrank to its intercept; it is the same number for every type and cannot mark a type as above chance. Tm20 (0.1268 vs its own time control 0.1325) and Mi2 (0.1258 vs 0.1270) must be reported as not distinguishable from zero, not as the bottom of a ranking. A scene-level bootstrap costs CPU minutes.
- The headline column sums two different quantities. by_stage.csv already decomposes real = floor + scene + frame; the split is type-specific (I measured stage->scene R2 = 0.319 against stage->frame R2 = 0.082, so the 'stage-wise' signal lives mostly in scene identity). Ranking by frame instead of total moves L1 -34 ranks, CT1(M10) -33, L2 -31, C3 -21, and lifts L3 +12, Mi4 +12, Mi9 +11, Tm9 +10, Tm3 +10. Report the frame component as primary.
- The quality-against-count control is broken and cheap to fix. I reproduced it exactly: 17 of 65 curves are non-monotonic (C2, L4, Mi1, Mi14, Mi2, T4a, T4b, T4c, T5a, T5d, Tm2, Tm20, Tm4, Tm5c, TmY14, TmY15, TmY18). More cells cannot carry less information, so this is per-type noise of order +-0.1 — the same size as the differences the ranking asserts. Average over several random subsets per count.
- One split is not enough. config.toml:40-42 holds out 5 of 23 Sintel scenes at seed 0 with no repeats. Auditor 1 reports seed 0 is the MINIMUM of six fresh splits for both Mi1 (0.414 vs mean 0.605) and T5a (0.188 vs 0.492, across-split SD 0.159) and the maximum for none — i.e. the published split is biased in exactly the direction of the claim. I did not re-run the splits. Ten repeats with a per-type interval is CPU-hours, not dollars.
- Item 6 (central brain) is affordable but not identifiable at the stated scope. Auditor 5's compute attack failed cleanly — the whole male brain is ~17 GB of autograd graph, 4 GB checkpointed, one A100 — so money and memory are not the constraint. What bites is that 'VPNs and their targets' reaches 3,608 of 6,313 non-CX central-brain types, taking free parameters from 734 to ~95,265, with >99.3% having no FlyVis source and 38.9% of type pairs pooling a single edge; and that the named validation target, DANDI 000727 at 1.8 Hz voxel-level, cannot constrain a 50 Hz per-cell-type model. I did not verify those counts myself (151M-row feather scans). Cut the scope to the LC/LPLC bottleneck as a readout over a frozen optic lobe, and move 'then the central complex' behind its own gate.
- Modal money is not a constraint anywhere in this project. Auditor 3's arithmetic (250k iterations x batch 4 x 19 frames, A100-40GB at $2.10/h, model 0.55x FlyVis's edge count) puts a 50-model MaleCNS ensemble at roughly $110-900 depending on a per-iteration time nobody has measured. That figure is an extrapolation — there is no GPU here and the reference publishes no compute — but even the pessimistic end is not what decides this project.

## survives

- There is real, non-trivial signal in the map, and it carries biology the model was not fit to. I verified from by_stage.csv that the frame component separates Borst's published sustained class (L3 0.629, Mi4 0.634, Mi9 0.592, Tm9 0.530; mean 0.596, min 0.530) from the transient class (L1 0.336, L2 0.337, L4 0.414, Mi1 0.282, Tm1 0.512, Tm2 0.423, Tm3 0.523, Tm4 0.296; max 0.523) with zero overlap, across three anatomical stages. The map is reading temporal-filter identity — which is a result, just not the one advertised.
- The pipeline is correct where it must be. Photoreceptors return PixCorr 0.9992-1.000 with identification 1.00 against chance 0.05, which confirms frame alignment and hexal ordering; my independent refits reproduce the published fits to four decimals (L1 0.8485, Mi4 0.7797, R1 0.9999, T5a 0.1878). Nothing in the decoder stack is broken.
- The column inference is not the ceiling. My best attack route here died on the record: 0.969 exact against the 15 tagged types, 0.958 for the partner-median fallback, 0.986 within one column (runs.jsonl:2-3). ISS-0001 (Tm4, 47% disagreement) is one type, and it is recorded as a defect in the third-party annotation, not hidden.
- The project's own controls already caught the worst failure before any auditor did. The moving-edge protocol was killed by its own sample-shuffle control (0.903 control against 0.902 real, the control at least as high in 55 of 65 types) and the report says so in plain words, claiming no decodability number from it. That is the discipline AGENTS.md asks for, working.
- The Sintel map is not yet a claimed result. map.csv and by_stage.csv were written at 05:12, after the step-4 report (04:55), and there is no runs.jsonl entry for them — the last rows are the edges run. So every attack above lands on a draft figure at exactly the moment it is cheapest to change, not on a published claim.
- Compute and memory for the central brain, and money for training, are not blockers anywhere (see costly item 9). The attacks that assumed scale would kill this project failed.
- Novelty appears to hold: two auditors independently checked and found no per-cell-type stimulus-decodability map for any insect — Lappalainen et al. decode in the encoder direction (activity -> flow), Zhou & Hasler do RSA/CKA without a per-type ordering, Dhiman & Panwar and Sci Rep 2026 decode motion labels, not the stimulus. I did not verify these myself and they should be checked against the papers before citation.

## order_change

Two zero-cost local steps must precede the next priced gate, and one of them may change the roadmap's own rationale. (1) Move the 'Ablations on model zero' line out of Not started and run it BEFORE item 3: rebuild model zero with the connectome-adaptive initialisation or the <N>_fv/<N>_mc rescale (flydream/model/zero.py:96-106), re-measure T4/T5 DSI with the existing step-2 code, and only then decide CT1 (ISS-0002). This is minutes of CPU and it gates a $110-900 Modal run. It may also unsettle a standing decision: DECISIONS.md:190-207 put item 4 ahead of item 3 because model zero's DSI was 0.020 against FlyVis's 0.391 and 'a decoder read from model zero's motion pathway would be reading near-silence'. If a large share of that 20x is the scale mismatch, the premise of that reordering is weaker than it looked — the ordering itself stays sensible (debugging decoders against validated activity is still right), but the reason recorded in DECISIONS.md must be corrected rather than left standing. (2) Inside item 4, sweep `lags` (config.toml:37) with matched controls before anything about ordering is written down or plotted; a published ordering that inverts under one config line is not a result. Neither step changes the queue's shape: 4 then 3 then 5, 6, 7 stands. Also a records defect: ROADMAP.md:5 still says 'idea and research done, no code yet' while the same file records steps 1, 2 and part of 4 as built and reported.

## cheapest_next_falsification

Rebuild model zero with syn_strength renormalised by <N>_fv/<N>_mc (or simply left at FlyVis's own connectome-adaptive init, 0.01/<N>_malecns) and re-run the existing moving-edge protocol on members 000-002. Everything needed is already written: the step-2 report puts the full 9-network run at 8 minutes of local CPU, no Modal, no download, no gate. It answers the single question on which the most money and the most roadmap rationale depend — is MaleCNS's T4/T5 selectivity collapse (0.020 vs 0.391) a property of the connectome or an artifact of the transplant? — and I have already verified the mechanism in code and measured the mismatch factors (median 1.847x, Tm9->T5 3.2-4.2x, max 34x), so the experiment is confirmation of a specific prediction, not a fishing trip. Second cheapest, and nearly as decisive: re-run the 65-type Sintel map at lags (0,2,4) with the time-shuffle control refit at the same window — about 12 s per type per condition on this machine, so under an hour for the full map — which decides whether the first paper's figure exists in the form the roadmap promises.

## disagreements

- Whether the Sintel map exists at all. Auditor 6 states flatly that map.csv does not exist and that item 4 has produced zero decodability numbers; auditors 1, 3, 4 and 5 read and analyse it. Resolved by timestamp: pairs.npz 05:04, map.csv and by_stage.csv 05:12, and auditor 6 checked before that. Auditor 6's derived conclusions about item 4's emptiness are stale, though its core arithmetic about the parked substrate leg is unaffected.
- What the low T4/T5 scores mean — the sharpest contradiction, and I resolved it by measurement. Auditor 2 converts them into an information claim ('under 1 of 721 dimensions at T4a and T5a') and auditor 5 uses the same numbers to pre-register the central-brain continuation of the map as a null. Auditor 1 says they are an artifact of lags = [0]. I reran it: T5a's control-corrected score rises from 0.057 to 0.625 and its raw PixCorr from 0.188 to 0.782 with a 60 ms window. Auditor 1 is right; auditors 2 and 5 both built conclusions on a decoder artifact, and auditor 2's own closing argument (the decoder class sets the numbers, not the information) refutes its own headline.
- What caused the MaleCNS DSI collapse. The project's own step-2 report names four candidates (missing CT1, median parameters for 56 pairs, filter-scale mismatch on wide-field TmY types, four absent types). Auditors 2 and 6 treat DSI 0.020 as a settled property of the substrate and reason from it. Auditor 3 says most of it is a parameter-scaling bug in the transplant, plus CT1. I verified auditor 3's mechanism in flyvis's source and measured the mismatch factors; neither the project's report nor four of six auditors considered it.
- Whether the model is recurrent. reports/Коннектом мухи и план проекта.md:84 says there is no recurrence capable of generating structured activity; auditor 4 counts 24 excitatory self-type edges in data/ol/filters_R.json (Tm3 13.72, T2 13.25, T4b 11.95 summed filter weight) and says the model decays because the transplanted gains are subcritical, not because it is feed-forward. No other auditor engaged. If auditor 4 is right, the dream chapter's spontaneous-activity regime is a modeller's free parameter between 'dead in 60 ms' and the 1e8 runaway step 2 already hit — which is a more honest framing than either document currently carries.
- Whether the fly connectome beats a degree-matched null. Auditor 6 sets conn2res (Nature Communications 2024: fruit fly the only species failing, p = 0.11) against bioRxiv 2025.10.29.685101 (p < 0.01 for all species, but with a weaker weight-preserving null) and against FlyGM's 1.6% honest-null gap versus its 15.1% Erdos-Renyi headline. It names the contradiction itself rather than smoothing it. Only relevant to the parked leg, but the recorded control condition in ROADMAP's Parked section ('shuffled to the same degree distribution') is the right one and should stay.
- Method rather than fact: auditor 2 sampled seven ensemble members' operating points and found L1, L2 and Am never cross the release threshold in member 000 specifically; auditor 1 argued the ensemble case from validation losses alone. I confirmed auditor 2's measurement exactly on the project's own pairs.npz (L1 max -0.2920, L2 max -0.2617, Am max -0.4690 across all 189 x 40 x 721 entries, frac_pos = 0.0000), so in the member the entire decoder stack uses, the two principal lamina channels compute a decodable voltage and transmit exactly zero current downstream forever, because flyvis rectifies presynaptic voltage (dynamics.py:214) while the decoder reads the unrectified state. Neither auditor drew the sharpest consequence: this is precisely a defect flyvis's own voltage-trace validation cannot see, and it belongs in ISSUES.md before the R -> L -> Mi/Tm -> T4/T5 figure is drawn from this member. Nobody found what I did — that the ensemble ids are rank-ordered by validation loss, so member 000 is the best of 50 by construction and step 2's 000/001/002 are the top three.
