## Часть A. Научно обоснованные рычаги уменьшения стоимости одного сэмпла

### A0. Базовые числа референса (что вообще уменьшать)

#### Takeaway
Опубликованная конфигурация FlyVis — 45 669 нейронов и 1 513 231 связь на 721 гексагональной
колонке (extent 15, 31 колонка поперёк), интегрирование Эйлера, dt = 5 мс, клипы ~19 кадров при
50 Гц (~380 мс), ансамбль из 50 моделей, и всего 734 свободных параметра. Это расходится с
числами в задании (31,5 k нейронов, 1,35 M рёбер) — расхождение надо разрешить до планирования.

#### Cited Findings
- «The model comprises 45,669 neurons across 64 cell types with 1,513,231 synaptic connections.
  The hexagonal lattice spans 721 columns (31 columns across)» — [Lappalainen et al., *Connectome-constrained networks predict neural activity across the fly visual system*, Nature 2024, PMC-версия](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/) (просмотрено 2026-09-18)
- Оптимизируются только **734 свободных параметра**: 65 потенциалов покоя, 65 постоянных времени,
  604 синаптических масштабных коэффициента α(ti,tj) — [там же](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/)
- Обучение: 23 последовательности Sintel (20–50 кадров, 24 fps, 1024×436); вход — **19
  последовательных кадров при 50 Гц, ≈380 мс** модельного времени — [там же](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/)
- Ансамбль — **50 task-optimized моделей** из одного и того же коннектомного ограничения — [там же](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/)
- Реализация: динамика симулируется «through Euler integration using a small number of
  element-wise, scatter and gather operations at each time step», что авторы сочли эффективнее
  одной свёртки или отдельных свёрток на тип клетки, «since each cell type has its own receptive
  field and the number of cells per type is relatively small» — [пересказ Methods по результатам поиска, Nature 2024](https://www.nature.com/articles/s41586-024-07939-3) (просмотрено 2026-09-18)
- Независимая работа 2026 года воспроизводит ту же конфигурацию: «flyvis recurrent neural network
  … 45,669 nodes and 1,513,231 directed edges», «734 trainable parameters and 2959 fixed
  parameters» — [*Topological Sensitivity in Connectome-Constrained Neural Networks*, arXiv 2604.04033](https://arxiv.org/html/2604.04033v1) (просмотрено 2026-09-18)

#### Inferences
- **Вывод.** Цифры задания (31,5 k нейронов, 1,35 M рёбер) не совпадают ни с Nature 2024, ни с
  независимым воспроизведением 2026 года. Вероятнее всего, они относятся к другому построению
  коннектома (иной фильтр по числу синапсов, иной набор типов клеток или MaleCNS вместо
  FlyWire/Janelia-версии), а не к опубликованной конфигурации FlyVis. Перед тем как считать
  «стоимость сэмпла», надо зафиксировать, какое из двух построений является базой проекта.
- **Вывод.** 734 обучаемых параметра при 1,5 M рёбер означают, что стоимость шага почти целиком
  определяется числом **рёбер × шагов интегрирования × кадров**, а не числом параметров. Все
  рычаги ниже бьют именно по этому произведению.

#### Gaps
- Точное время обучения одной модели и тип GPU в Lappalainen et al. найти не удалось: страница
  PMC в пересказе дала «specific training hardware and wall-clock time aren't detailed».
- Число итераций обучения: пересказ PMC назвал «approximately 250,000 iterations», но это число не
  подтверждено прямым чтением Methods и не подтверждено вторым источником. **Не использовать без
  проверки.**
- Прямое чтение bioRxiv-препринта (полный текст Methods) не удалось: сервер вернул HTTP 429.
- Конфигурационные YAML-файлы FlyVis (`config/`) по прямым URL на GitHub вернули 404; проверить
  значения по умолчанию (`extent`, `dt`, `n_iters`, `batch_size`) можно только из локальной копии
  репозитория.

### A1. Меньше колонок (уменьшенный hexagonal extent)

#### Takeaway
Параметры FlyVis разделяются **по типу клетки и по отводу фильтра (source_type, target_type, du,
dv)**, поэтому extent меняет только число ретинотопических колонок, на которые эти общие параметры
рассыпаются, — число свободных параметров остаётся тем же. Это делает обучение на меньшем extent с
переносом на полный extent архитектурно возможным, но прямого опубликованного эксперимента
«обучили на малом extent — провалидировали на 721 колонке» я не нашёл.

#### Cited Findings
- «Flyvis shares every parameter by cell type and by (source_type, target_type, du, dv) filter tap,
  so extent changes only how many retinotopic columns those shared parameters are scattered onto:
  734 free parameters for the current model and 800 for the conductance one at extent 8 and at
  extent 15 alike» — сторонний репозиторий, [allierc/connectome-gnn PR #61](https://github.com/allierc/connectome-gnn/pull/61) (по пересказу поиска, 2026-09-18). **Сторонний источник, не рецензирован.**
- «extent 8 is 13,741 neurons and 434,112 edges, the network the teacher-student twin was fitted
  on; the published protocol is extent 15, 45,669 and 1,513,231» — тот же сторонний источник,
  [allierc/connectome-gnn](https://github.com/allierc/connectome-gnn) (2026-09-18). **Не проверено.**
- «the connectome extent fixes how many photoreceptors the network has and the boxfilter extent
  fixes how many hexals the movie is rendered onto; setting one alone makes `Stimulus.add_input`
  refuse the batch, because the rendering still carries extent 15's 721 hexals» — тот же источник
  (2026-09-18). Практическое предупреждение: **менять надо оба extent согласованно.**
- Историческая предшественница FlyVis (гексагональная решёточная свёрточная сеть) явно строит
  модель как свёртку по гексагональной решётке с разделяемыми весами — [*A Connectome Based Hexagonal Lattice Convolutional Network Model of the Drosophila Visual System*, arXiv 1806.04793](https://arxiv.org/pdf/1806.04793) (просмотрено 2026-09-18)

#### Inferences
- **Вывод (сильный, архитектурный).** Раз параметры разделяются по типу и по отводу фильтра, веса,
  обученные на extent 8, синтаксически переносимы на extent 15 без изменения размерности. Это
  **рычаг, меняющий только прогон**, при условии, что обученная модель валидируется на полном
  extent 15.
- **Вывод (осторожный, научный).** Перенос не бесплатен по существу: у краевых колонок рецептивные
  поля обрезаны, и доля «краевых» нейронов при extent 8 гораздо выше, чем при extent 15
  (периметр/площадь). Значит, статистика входа, которую видит модель, при малом extent смещена, и
  задача optic flow (глобальное движение) на маленьком поле зрения буквально другая. Поэтому
  уменьшение extent — **рычаг, меняющий модель**, и требует валидации: прогнать обученную на малом
  extent модель на полном extent 15 и сравнить tuning-свойства (DSI/OSI по типам клеток) и
  task-loss с моделью, обученной сразу на 721 колонке.
- **Вывод (масштабирование).** 434 112 / 1 513 231 ≈ 0,287. Если стоимость шага линейна по числу
  рёбер, extent 8 даёт ~3,5× удешевления одного сэмпла относительно extent 15.

#### Gaps
- Не найдено ни одной **рецензированной** работы, которая обучала FlyVis-класс модель на
  уменьшенном extent и измеряла потерю точности при переносе на полный extent. Единственное
  свидетельство — сторонний репозиторий, где extent 8 использован для «teacher-student twin», без
  опубликованной валидации.
- Не найдено чисел нейронов/рёбер для промежуточных extent (например, 10, 12), чтобы построить
  кривую «стоимость vs extent».

### A2. Больший dt / меньше шагов интегрирования

#### Takeaway
FlyVis использовал шаг Эйлера 5 мс и прямо отметил, что шаг **меньше 20 мс** даёт качественно
лучшую производительность на задаче; то есть 20 мс — это названная авторами граница, за которой
качество портится, а не безопасное значение. Это самый «дешёвый» по коду и самый опасный по науке
рычаг.

#### Cited Findings
- «Euler integration with a time step of 5 ms for most simulations», и авторы отмечают, что «an
  integration time step smaller than 20 ms yielded qualitatively superior task performance» —
  [Lappalainen et al., Nature 2024 (PMC)](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/) (просмотрено 2026-09-18)
- Вход подаётся при 50 Гц (кадр = 20 мс), то есть при dt = 5 мс на каждый кадр приходится 4 шага
  интегрирования — [там же](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/)
- Chen et al., *Decoding dynamic visual scenes across the brain hierarchy*, PLOS Comput Biol 2024
  (том 20, август 2024) — это работа **по мыши** (Allen Visual Coding — Neuropixels), а не по
  дрозофиле: «a 120-second movie with a total of 3600 frames», «3200 frames as the training and
  validation set and 400 frames as the test set»; **явного размера временного бина в тексте не
  указано, и анализа влияния размера бина на точность декодирования нет** — [PLOS Comput Biol 2024, pcbi.1012297](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1012297) (просмотрено 2026-09-18)
- Единственная показанная в Chen et al. робастность — по размеру популяции: насыщение около «500
  cells» для зрительных областей и «around 1000 cells» для гиппокампа; «decoding performance is
  robust to the variation of model parameter settings» относится к размеру фильтра модели, не к
  временному разрешению — [там же](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1012297)

#### Inferences
- **Вывод.** Задание проекта (40 шагов Эйлера по dt = 0,02 с = 20 мс, то есть 0,8 с) уже стоит
  **на самой границе**, названной FlyVis как «хуже, чем меньше 20 мс». Увеличивать dt дальше без
  измерения — прямое нарушение референса. Двигаться надо в противоположную сторону (dt = 5–10 мс) и
  доказывать, что 20 мс достаточно, а не наоборот.
- **Вывод.** dt — **рычаг, меняющий модель**. Постоянные времени мембраны являются обучаемыми
  параметрами; при слишком большом dt явная схема Эйлера устойчива только при dt < τ, и обучение
  будет просто выбирать τ, совместимые с шагом, то есть подгонять биофизику под численную схему.
  Валидация: сравнить обученные τ по типам клеток и DSI/OSI при dt = 5, 10, 20 мс на одном сиде.
- **Вывод.** Chen et al. PLOS CB 2024 **не является источником по выбору шага интегрирования** для
  этого проекта: другая система, другая модальность, и нужного анализа в ней нет. В отчёте её лучше
  цитировать только по декодируемости по уровням иерархии, как и заявлено в AGENTS.md.

#### Gaps
- Не найдено количественного графика «task loss vs dt» в Lappalainen et al. — есть только
  качественное утверждение про порог 20 мс. Найти соответствующий supplementary-рисунок не удалось
  (доступ к полному Methods/Supplement не получен).

### A3. Короче клипы / меньше кадров на сэмпл

#### Takeaway
FlyVis обучался на очень коротких клипах — 19 кадров при 50 Гц, ≈380 мс, что вдвое короче
предполагаемых проектом 0,8 с. Здесь есть запас удешевления, подтверждённый опубликованной
практикой.

#### Cited Findings
- «Input sequences consisted of 19 consecutive frames at 50 Hz temporal resolution (approximately
  380 ms of simulated time)» — [Lappalainen et al., Nature 2024 (PMC)](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/) (просмотрено 2026-09-18)
- Исходные клипы Sintel — 20–50 кадров при 24 fps, то есть исходного материала длиннее 19 кадров
  при 50 Гц физически мало — [там же](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/)

#### Inferences
- **Вывод.** 19 кадров при 50 Гц ≈ 0,38 с ≈ 76 шагов Эйлера при dt = 5 мс. Проектные 40 шагов по
  20 мс = 0,8 с — это **длиннее по модельному времени, но вдвое грубее по времени**. Прямое
  сравнение «40 шагов дешевле 76 шагов» верно по цене, но эти два режима не эквивалентны научно.
- **Вывод.** Длина клипа — **почти чистый рычаг прогона**, если задача (optic flow) оценивается
  покадрово и сеть успевает выйти из переходного процесса. Риск: слишком короткий клип не даёт
  рекуррентной динамике устояться, и обучаемые τ сместятся. Валидация дешёвая: обучить при 19 и при
  40 кадрах, сравнить loss на общем валидационном наборе фиксированной длины.
- **Вывод.** Стоимость сэмпла линейна по числу шагов; переход с 40 шагов на 19 при том же dt даёт
  ~2,1× удешевления.

#### Gaps
- Не найдено исследования (ни в FlyVis, ни в follow-ups), измеряющего task-loss как функцию длины
  обучающего клипа.

### A4. Прунинг слабых рёбер

#### Takeaway
В FlyVis, по прочитанному пересказу Methods, **порога по числу синапсов не применялось** —
используются все измеренные синапсы, а вес пропорционален числу синапсов. Поэтому прунинг слабых
рёбер в этом проекте будет **отступлением от референса**, а не воспроизведением его, и требует
собственной валидации. Опубликованных исследований эффекта порога именно на FlyVis-класс модели я
не нашёл.

#### Cited Findings
- «No explicit minimum synapse threshold was applied as a filter. Instead, the model uses all
  measured synapses from the connectome reconstruction, with synaptic weights proportional to
  synapse counts between identified cell type pairs» — пересказ Methods,
  [Lappalainen et al., Nature 2024 (PMC)](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/) (просмотрено 2026-09-18). **Отрицательное утверждение из машинного пересказа — проверить по оригиналу.**
- В коннектомной литературе широко используется порог **5 синапсов на связь**, при этом
  робастность к вариации порога проверяется отдельно; для визуализации применяют >25 синапсов, для
  фильтрации по нейропилям — ≥100 синапсов на нейрон — [по результатам поиска, обзорные и методические источники, включая](https://www.nature.com/articles/s41586-024-07968-y) *Network statistics of the whole-brain connectome of Drosophila*, Nature 2024 (просмотрено 2026-09-18)
- «Differences in synapse detection and thresholding impact topological metrics such as connection
  probability and reciprocity» — [там же / сопутствующие методические источники](https://www.nature.com/articles/s41586-024-07968-y) (2026-09-18)
- Работа, специально изучавшая чувствительность FlyVis к топологии, **прунинг не исследовала**: «The
  paper contains no edge pruning or weight-threshold experiments», вместо этого сравнивались
  случайный граф и degree-preserving rewired null model через «directed double-edge swaps applied
  to the non-loop edges» — [arXiv 2604.04033](https://arxiv.org/html/2604.04033v1) (просмотрено 2026-09-18)

#### Inferences
- **Вывод.** Прунинг — **рычаг, меняющий модель**, причём самый идеологически нагруженный: он
  меняет сам объект («коннектом — это ограничение»). Если его применять, то как настройку в
  `config.toml` с указанной причиной и с контролем: кривая «task loss и DSI/OSI vs порог по
  синапсам» на 3–4 значениях порога (0, 3, 5, 10) на одном сиде.
- **Вывод (экономический).** Распределение весов в коннектоме дрозофилы сильно скошено: большинство
  связей слабые. Порог 5 синапсов обычно убирает большую долю рёбер при малой доле суммарного веса.
  Это делает прунинг потенциально самым выгодным рычагом по отношению «экономия / изменение
  динамики». **Конкретной доли рёбер и веса, отсекаемых порогом 5 в оптической доле MaleCNS, я не
  нашёл** — это надо посчитать по локальным таблицам проекта, не по литературе.
- **Вывод.** Существование degree-preserving rewired null model в arXiv 2604.04033 даёт готовый
  шаблон контроля для этого проекта: любое утверждение «прунинг не навредил» должно стоять рядом с
  «а перемешанная связность — навредила».

#### Gaps
- Отрицательное утверждение «FlyVis не применял порога» получено из машинного пересказа PMC, а не
  из прямого чтения Methods. Требуется проверка по оригиналу (или по коду `flyvis`), прежде чем
  цитировать в отчёте.
- Нет ни одной работы, измеряющей task-loss FlyVis как функцию порога по числу синапсов.

### A5. Обучение на подмножестве типов клеток / заморозка параметров

#### Takeaway
Свободных параметров всего 734 при 2959 фиксированных, поэтому заморозка параметров почти не
экономит вычисления — стоимость определяется прямым/обратным проходом по 1,5 M рёбрам, а не числом
обучаемых чисел. Подмножество типов клеток — это уже другой коннектом.

#### Cited Findings
- «734 trainable parameters and 2959 fixed parameters» — [arXiv 2604.04033](https://arxiv.org/html/2604.04033v1) (просмотрено 2026-09-18)
- Разбиение 734 параметров: 65 потенциалов покоя, 65 постоянных времени, 604 синаптических α —
  [Lappalainen et al., Nature 2024 (PMC)](https://pmc.ncbi.nlm.nih.gov/articles/PMC11525180/) (просмотрено 2026-09-18)

#### Inferences
- **Вывод.** Заморозка части из 734 параметров экономит только память оптимизатора (килобайты) и
  ничего в вычислениях: backward всё равно проходит по всему графу рекуррентной динамики. Это
  **не рычаг стоимости**. Исключение — если заморозка позволяет вовсе отбросить backward через
  часть временных шагов (truncated BPTT), но это отдельный приём, см. Gaps.
- **Вывод.** Обучение на подмножестве типов клеток эквивалентно удалению узлов графа и является
  **рычагом, меняющим модель** сильнее прунинга рёбер: удалив тип, вы удаляете пути. Оправдано
  только если проект явно заявляет более узкую цель (например, только ON/OFF-пути до T4/T5).

#### Gaps
- Не найдено работ по truncated BPTT / усечению обратного прохода по времени в моделях
  FlyVis-класса, хотя это стандартный приём в RNN и напрямую бьёт по стоимости 40 шагов. Это
  заметный пробел в литературе и кандидат на собственный эксперимент проекта.

### A6. Transfer / warm-start: обучение от параметров другой модели

#### Takeaway
FlyVis раздаёт предобученные модели, и единственная найденная работа, где сравнивали старт с
чекпойнта и общую случайную инициализацию, показала, что **общая случайная инициализация убирала
раннее преимущество по loss** — то есть наблюдаемое «быстрое» поведение объяснялось инициализацией,
а не связностью. Количественных данных «warm-start экономит N итераций» для FlyVis нет.

#### Cited Findings
- Flyvis предоставляет предобученные модели и туториалы анализа — [TuragaLab/flyvis](https://github.com/TuragaLab/flyvis) (просмотрено 2026-09-18)
- «Training both graphs from a shared random initialization removed the early loss advantage» при
  сравнении коннектомно-ограниченной модели с контрольными сетями; сравнение велось по matched
  optimization steps (5 и 10 шагов) на задаче MovingEdge, Adam с lr = 10⁻³ — [arXiv 2604.04033](https://arxiv.org/html/2604.04033v1) (просмотрено 2026-09-18)
- Общая литература по warm-starting предупреждает, что дообучение с тёплого старта может ухудшать
  обобщение по сравнению с обучением с нуля — [*On Warm-Starting Neural Network Training*, arXiv 1910.08475](https://arxiv.org/pdf/1910.08475) (просмотрено 2026-09-18)

#### Inferences
- **Вывод.** Warm-start — **рычаг, меняющий модель в скрытом виде**: он ломает независимость членов
  ансамбля. FlyVis получает разброс свойств именно из 50 независимых инициализаций; если все члены
  стартуют с одного чекпойнта, «ensemble spread», который AGENTS.md требует показывать рядом с
  каждым числом, перестаёт быть тем, чем был у референса.
- **Вывод.** Допустимое применение warm-start, не ломающее науку: перенос **между extent** (обучить
  на малом extent, дообучить на полном) и перенос **между dt** (обучить при 20 мс, дообучить при
  5 мс). В обоих случаях ансамблевая независимость сохраняется, если перенос делается почленно —
  член i малого extent порождает член i полного extent.
- **Вывод.** arXiv 2604.04033 даёт прямой методический урок: любое утверждение «warm-start ускоряет
  сходимость» должно сравниваться при **общей случайной инициализации** и при **согласованном числе
  шагов оптимизации**, иначе измеряется инициализация, а не перенос.

#### Gaps
- Не найдено ни одного измерения вида «N итераций с нуля vs M итераций с тёплого старта до того же
  loss» для FlyVis или родственных коннектомных моделей.

### A7. Сводка: что меняет модель, а что только прогон

| Рычаг | Ожидаемая экономия | Меняет модель? | Требуемая валидация |
|---|---|---|---|
| Меньше колонок (extent 8 vs 15) | ~3,5× (по числу рёбер: 434 112 / 1 513 231) — цифра из непроверенного стороннего источника | **Да** (краевые эффекты, другая задача на малом поле) | Прогон обученной модели на extent 15; DSI/OSI по типам и task-loss vs модель, обученная на 15 |
| Больший dt (20 мс) | линейно по числу шагов | **Да** (устойчивость Эйлера, подгонка τ под схему) | task-loss и обученные τ при dt = 5/10/20 мс |
| Короче клипы (19 vs 40 кадров) | ~2,1× | Почти нет, при контроле переходного процесса | общий валидационный набор фиксированной длины |
| Прунинг слабых рёбер | не измерено; потенциально велика | **Да**, и идеологически (коннектом — это объект) | кривая loss/DSI vs порог + rewired-контроль |
| Заморозка параметров | ~0 | нет | не нужна |
| Подмножество типов клеток | пропорционально удалённым рёбрам | **Да**, сильно | переформулировка научной цели |
| Warm-start | не измерено | **Да**, через потерю независимости ансамбля | matched-steps сравнение при общей случайной инициализации |

### B2. L4 vs T4 на memory-bound gather/scatter: дешевле ли L4 за сэмпл?

#### Takeaway
По опубликованной пропускной способности памяти L4 и T4 **практически одинаковы** (300 GB/s у обеих
по датащитам; у T4 в product brief встречается 320 GB/s). Для чисто memory-bound gather/scatter это
означает отсутствие выигрыша, тогда как L4 на Modal стоит в 1,354 раза дороже. Следовательно, по
опубликованным числам пропускной способности **L4 не дешевле T4 за сэмпл** для этой нагрузки —
выигрыш может прийти только из кэша, bf16 или из того, что нагрузка на деле не полностью
memory-bound.

#### Cited Findings
- L4: «24GB of GDDR6 ECC memory and 300GB/s of memory bandwidth» — [NVIDIA L4 Datasheet (PDF, зеркало AceCloud)](https://acecloud.ai/wp-content/uploads/2025/11/Nvidia-L4-GPU-Datasheet.pdf) (просмотрено 2026-09-18)
- T4: датащит указывает **300 GB/s**, при этом в product brief NVIDIA фигурирует **320 GB/s** —
  расхождение зафиксировано в обсуждении на форуме NVIDIA — [NVIDIA Developer Forums: «NVIDIA Tesla T4 memory bandwidth»](https://forums.developer.nvidia.com/t/nvidia-tesla-t4-memory-bandwidth/162933) (просмотрено 2026-09-18); [T4 datasheet (PDF)](https://www.thinkmate.com/wwwinc/tm/servers/gpx/nvidia-t4-datasheet-a4-partner-772234-r14-web.pdf)
- AWS заявляет для G6 (L4) «2x better performance for deep learning inference and graphics
  workloads compared to EC2 G4dn instances» (G4dn = T4) — [aws.amazon.com/ec2/instance-types/g6](https://aws.amazon.com/ec2/instance-types/g6/) (просмотрено 2026-09-18). Это заявление вендора о **inference/graphics**, не о memory-bound gather/scatter.

#### Inferences
- **Вывод (главный).** Порог безубыточности L4 на Modal = 1,354×. Пропускная способность памяти
  0,94–1,00× (300/320 … 300/300). Если нагрузка действительно упирается в пропускную способность
  DRAM, L4 даст ~1,0× скорости при 1,354× цены → **T4 дешевле за сэмпл примерно в 1,35 раза**.
- **Вывод (где L4 всё-таки может выиграть).** Две опубликованные архитектурные разницы работают в
  пользу L4 на gather/scatter: (1) L4 (Ada, AD104) имеет существенно больший L2-кэш, чем T4
  (Turing, TU104) — при 1,5 M рёбер и 721 колонке индексные буферы и векторы состояния могут
  частично умещаться в L2, и тогда нагрузка перестаёт быть DRAM-bound; (2) T4 (Turing) **не имеет
  аппаратной поддержки bf16**, а L4 (Ada) имеет — при обучении в bf16 T4 вынуждена использовать
  fp16 с риском переполнения либо fp32 с удвоенным трафиком памяти. **Конкретных чисел размера L2 у
  обеих карт я в датащитах в рамках этой сессии не подтвердил — см. Gaps.**
- **Вывод (что измерять, а не гадать).** Спор решается одним дешёвым замером, который у проекта уже
  есть в форме `smoke_batch`: одинаковый батч, одинаковый dt и extent, на T4 и на L4, метрика —
  с/итерация. Дальше $/10⁶ сэмплов = (с/итерация ÷ размер батча) × 10⁶ × ($/ч ÷ 3600).
  При зафиксированной в репозитории оценке 0,434 с/итер на T4 (запись из коммита c98830e) L4
  окупается только если даст **< 0,321 с/итер**.
- **Вывод.** Заявление AWS «2×» не переносимо на эту задачу: оно про inference-бенчмарки, где
  используются тензорные ядра Ada и FP8/INT8, то есть compute-bound режим. Цитировать его как
  обоснование выбора L4 нельзя.

#### Gaps
- Не найдено ни одного бенчмарка L4 vs T4 **именно на разреженных gather/scatter** или на
  GNN/message-passing нагрузках. Все найденные сравнения — inference LLM/CV.
- Размеры L2-кэша T4 и L4 в рамках этой сессии из первичных датащитов не подтверждены; утверждение
  о «существенно большем L2 у Ada» — общее знание об архитектуре, требующее проверки по
  NVIDIA Ada Architecture Whitepaper.
- Реальная доля времени в gather/scatter против элементных операций для FlyVis-графа не
  опубликована никем; без профиля (например, `torch.profiler` на T4) утверждение «нагрузка
  memory-bound» само остаётся гипотезой.

## Gaps (сводно, что осталось непроверенным)

1. **Расхождение в размере сети.** Задание называет 31,5 k нейронов и 1,35 M рёбер; Nature 2024 и
   независимое воспроизведение 2026 года дают 45 669 и 1 513 231. Источник проектных чисел не
   установлен. Это надо разрешить до любого расчёта стоимости сэмпла.
2. **Methods FlyVis прочитаны только в машинном пересказе PMC.** Прямой доступ к полному тексту
   bioRxiv заблокирован (HTTP 429), YAML-конфиги на GitHub по прямым URL дали 404. Три ключевых
   числа — 250 000 итераций, отсутствие порога по синапсам, порог «меньше 20 мс» — нуждаются в
   проверке по оригиналу или по локальной копии `flyvis`.
3. **Нет опубликованного эксперимента «малый extent → перенос на 721 колонку».** Единственное
   свидетельство существования extent 8 — сторонний нерецензированный репозиторий.
4. **Нет кривой «task loss vs dt»** и **нет кривой «task loss vs порог по синапсам»** ни в одной
   найденной работе. Оба эксперимента придётся ставить самим, с контролем.
5. **Chen et al. PLOS CB 2024 не отвечает на вопрос о шаге интегрирования** — это работа по мыши,
   и анализа размера временного бина в ней нет.
6. **Цены GCP и AWS получены через агрегатор getdeploying**, а не с первичных страниц вендоров;
   страница GCP вернулась усечённой, страницы продуктов AWS цен не содержат.
7. **Цена Vast.ai на L4 расходится между источниками** ($0,20 spot / $0,25 on-demand на сайте
   Vast против $0,32 у агрегатора).

   опубликованную пропускную способность памяти и на цену Modal, а не на измерение.
